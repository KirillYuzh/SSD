# Задание 4. Аутентификация и авторизация в Spring Security

• Подключите Spring Security к своему проекту
• Настройте НТТР Basic Auth и CSRF-защиту для запросов, изменяющих данные;
• Реализуйте возможность получения и использования CSRF-токена;
• Обеспечьте согласованную работу механизмов безопасности с существующим REST
АРІ и бизнес-операциями.

## • Реализуйте аутентификацию и регистрацию пользователей

• Используйте базу данных для хранения учётных записей. При необходимости дополните существующую модель пользователя;
• Обеспечьте безопасное хранение паролей с использованием PasswordEncoder и
BCrypt;
• Реализуйте регистрацию с проверкой надёжности пароля и уникальности учётной записи;
• Предусмотрите учёт состояния пользователя при аутентификации. Конкретные состояния и ограничения определите самостоятельно исходя из логики приложения;
• Регистрация не должна позволять самостоятельно получать повышенные привилегии.

## • Настройте авторизацию

• Реализуйте не менее двух ролей с различными возможностями. При необходимости дополните их отдельными правами;
• Настройте доступ ко всем CRUD и бизнес-операциям с помощью SecurityFilterChain
и @PreAuthorize;
• Определите правила доступа исходя из назначения приложения и обязанностей пользователей;
• Возможность выполнения некоторых операций может зависеть не только от роли пользователя, но и от контекста операции;
• Правила авторизации должны согласовываться с ограничениями ранее реализованной бизнес-логики.

## • Предусмотрите корректную обработку отказов

• Приложение должно различать ошибки аутентификации, недостаточность полномочий и нарушения бизнес-ограничений;
• Учитывайте ситуации, отличные от основного сценария, и возможные попытки несанкционированного доступа;
• Обработка ошибок не должна раскрывать чувствительные данные. Способ реализации и необходимую степень детализации выберите самостоятельно.

## • Обновите коллекцию запросов

• Добавьте запросы для регистрации, получения CSRF-токена и работы с защищёнными операциями;
• Продемонстрируйте работу приложения от имени пользователей с различными правами;
• Коллекция должна позволять воспроизвести осмысленные сценарии успешного и неуспешного обращения к АРІ, включая бизнес-операции из предыдущего задания.
