# Задание 3. Базы данных и отношения между таблицами

• Подключите базу данных своему проекту
• Установите любую реляционную базу данных;
• Не забывайте убрать чувствительные данные в env;
• Создайте таблицы для каждой сущности вашей предметной области;
• Создайте связи между таблицами таким образом, чтобы модель данных отражала отношения сущностей выбранной предметной области;
• Определите, какие ограничения целостности естественно следуют из предметной области, и выразите их на уровне модели данных там, где считаете это уместным;
• Создайте пользователя БД с ограниченным набором ролей и используйте его для выполнения запросов из своего сервиса;
• Подготовьте несколько тестовых записей в ваших таблицах, чтобы было что проверять.
• Переведите существующее REST API своего проекта на работу с базой данных
• Контроллеры из Задания 2 должны работать с БД, а не со структурами в оперативной памяти.
• Добавьте в свой проект бизнес-операции
• Придумайте и реализуйте 5 законченных бизнес-операций, естественных для выбранной предметной области;
• Минимум 2 бизнес-операции должны затрагивать 2 сущности одновременно;
• CRUD-операции не считаются бизнес-операциями. Операции поиска, не затрагивающие минимум 2 сущности, не считаются бизнес-операциями;
• Результат выполнения бизнес-операции должен зависеть от текущего состояния связанных объектов;
• После выполнения операции данные предметной области должны оставаться согласованными;
• Не все бизнес-операции должны быть допустимы для любого состояния данных;
• Бизнес-операции должны сохранять корректное поведение не только в основном сценарии;
• Конкретные правила и ограничения выполнения бизнес-операций определите исходя из логики выбранной предметной области;
• При реализации бизнес-операций модель предметной области при необходимости может быть уточнена или дополнена,
• Способ обеспечения корректности и целостности бизнес-операций выберите самостоятельно.
• Структура приложения должна соответствовать выбранной предметной области
• Подготовьте коллекцию запросов, демонстрирующую работу ваших новых операций
• Добавьте все запросы в коллекцию: CRUD по каждой сущности и новые бизнес-операции;
• Коллекция должна позволять воспроизвести осмысленный сценарий работы приложения: от создания исходных данных до выполнения бизнес-операций с учётом возникающих изменений состояния.
• Подготовьте короткий README, достаточный для понимания назначения приложения, его основных сущностей и реализованных бизнес-возможностей
• README должен позволять по нему понять назначение приложения, его предметную модель и реализованные бизнес-возможности без изучения исходного кода.
